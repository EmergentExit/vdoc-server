# 对话 + 干活：并行分流方案（草案）

目标：像一个智能助手——可以随口聊天、陪你讨论论文怎么写；你真的要改文档时，干活的 agent 立刻动手，**改文档的速度不能比现在的 S3 慢**。

## 1. 现状（代码可溯源）

- Higgs 只当耳朵和嘴巴，自己不回答、不决定（`delegated-model.ts:15-18`；它自发的回复被取消，`:348-350`）。
- 每句话的最终转写由服务端直接交给 Pi（`:206-220`），闲聊也走 Pi，回复限一两句，历史只留 8 轮、每轮 1000 字（`:22-41`、`:245-246`）。
- Pi 的回复整段生成完才交给 Higgs 逐字朗读（`:402-407`）。
- 实测（#64 之后，S3，120 次）：最后一次写入中位 2.51 s，整轮结束 4.20 s。

结论：改文档已经很快，但**聊不深**（Haiku、两句话、短记忆），**长回答要等整段生成完才出声**。

## 2. 查到的资料

| 来源 | 要点 | 对我们的意义 |
|---|---|---|
| OpenAI GPT-Live-1（2026-09 上线 API） | 全双工语音模型，只负责对话，把推理和动作**委派给开发者自己的后端**（client delegation）；后台干活时它可以继续说话；打断说话不会取消后台任务。OpenAI 报告轮转延迟 0.798 s（gpt-realtime-2.1 为 1.41 s）。 | 和我们想要的结构完全一样，而且是官方方案。缺点：协议很新（`v1/live/sessions`），vRT 还没有适配器；委派事件不带用户原话，要自己从转写里拼；**文档没写支持哪些语言，中文必须实测**。 |
| OpenAI Realtime（gpt-realtime-2.1 / -mini） | 语音到语音，单会话里听、想、说、调工具；推理强度可调（默认 low）。 | 可以当"对话者"，用工具把任务交给 Pi（OpenAI 官方示例里的 Chat-Supervisor 模式）。缺点：要先由它决定调用工具，Pi 才开始，改文档会多一跳。 |
| OpenAI Chat-Supervisor 示例 | 实时模型负责寒暄和收集信息，需要工具或深度推理时说一句"我看一下"，再交给文本大模型。 | 证明"先说一句占位话，再交给强模型"是可行的体验；它自己承认这会带来少量额外延迟。 |
| Claude（Anthropic） | 查到的资料里 Claude API 没有实时语音接口。 | Claude 只当大脑（讨论论文、执行），声音必须用 Boson 或 OpenAI。 |
| Talker-Reasoner（DeepMind，arXiv 2410.08328） | "快思考的对话者 + 慢思考的执行者"，对话者在执行者干活时继续交流。 | 论文里可以直接引用的理论依据。 |
| Boson Higgs | 厂商称语音进到语音出约 700 ms；兼容 OpenAI Realtime 接口；支持函数调用。 | 现有方案，中文已验证。但代码注释记录过它忽略每轮单独给的指令（`:19`），当对话者时提示词约束力要实测。 |

## 3. 推荐方案：语音模型负责聊，服务端并行分流，Pi 负责干

```
用户说完 ──┬─→ 语音模型（对话者）马上接话：闲聊直接回答；要改文档时只说"好，我来改"
           │
           └─→ 服务端拿到最终转写，同时做两件事：
                 ① Pi 预取文档（只读，和现在一样）
                 ② 意图判断：规则 + Haiku，约 0.3–0.5 s
                    ├─ 干活 → Pi 用预取结果直接开工（和现在的 S3 一模一样）
                    ├─ 深度讨论 → 交给"专家"（Claude，强模型），结果由语音模型说出来
                    └─ 闲聊 → 取消 Pi（只读过文档，没有副作用）
```

1. **改文档不变慢**：意图判断藏在 Pi 预取的时间里；Pi 的启动、工具、提示词完全不变。判断拿不准时默认"干活"，因为 Pi 本来就能闲聊。
2. **聊天快**：语音到语音模型直接接话，不经过文字大模型和单独的语音合成。
3. **讨论得深**：遇到"论文第三章该怎么组织"这类问题，语音模型先说一句"我想一下"，服务端把问题和文档交给 Claude，拿到答案后一句一句交给语音模型读出来。
4. **讨论完能直接执行**：用户说"好，就按这个写"，路由判为"干活"，把最近几轮讨论（专家的提纲）放进 Pi 的任务包，Pi 照着写。
5. **不会两头说话**：同一时刻只有语音模型一个声音。Pi 的"改好了"排在当前这句话后面播报；Pi 干活过程中不出声。
6. **不会乱报完成**：语音模型的提示词禁止它说"已经改好了"，只有 Pi 的工具结果确认成功后才播报完成（OpenAI 的 voice agent 指南也要求口头确认必须和已完成的动作一致）。
7. **插话**：沿用现在的逻辑（停 / 附和 / 补充）。顺便把现在没接上的插话判断器接上，用来分辨"补充当前任务"和"一个新任务"。

### 语音层候选（同一个后端，换前台）

| 候选 | 预期优点 | 风险 | 何时选 |
|---|---|---|---|
| A. Boson Higgs（现在就有） | 不用改协议，中文已验证 | 当对话者时是否听提示词；聊天质量 | 先用它把后端做完、测完 |
| B. gpt-realtime-2.1-mini | 语音到语音，会话质量好，有推理强度可调 | 中文识别和发音要实测 | A 的聊天质量不够时 |
| C. GPT-Live-1 + client delegation | 官方的"对话 + 委派"，轮转最快（OpenAI 自报 0.8 s），后台干活时能继续聊 | 新协议要写适配器；语言支持未公开；委派事件不带原话 | 实测中文过关后，作为最终形态 |

**先做最有把握的一版**：后端（路由 + 专家 + Pi + 共享记忆 + 逐句播报）一次做好，语音层先用 A，然后在本地对 A/B/C 做同样的测试，按数据选定。

## 4. 指标与验收（全部先在本地跑）

| 指标 | 怎么测 | 验收线 |
|---|---|---|
| 改文档速度 | 现有 60 道题 × 2 次，S3 对比新方案，交错运行 | 最后一次写入、整轮结束都不比 S3 慢（置信区间包含 0 或更快），成功率不低于 S3 |
| 意图判断 | 新建约 100 句中文标注集（干活 / 讨论 / 闲聊 / 停止），文本离线跑 | "干活"召回 ≥ 98%（漏判会让指令变慢），判断耗时中位 ≤ 0.5 s |
| 聊天首句出声 | 用合成中文语音驱动，记录用户说完到第一段音频 | 闲聊 ≤ 1.5 s；深度问题先有占位话 ≤ 1.5 s，正式回答首句 ≤ 4 s |
| 听得准 | 同一批合成语音，计算转写字错率 | 不高于现在的 Boson |
| 讨论后执行 | 10 组"先讨论再说'就这么写'"的脚本对话 | Pi 写出的内容符合讨论出的提纲 |

## 5. 上线流程（按你的要求）

1. **本地**：实现 → 单元测试 → `npm run check` → 上面的指标全部过线。
2. **线上预览**：推到一个功能分支，Cloudflare 给这个分支生成预览部署（不影响正式线上）；在预览地址上用真实浏览器和真实语音测一遍。
3. **确认没问题后**才合并到 main，由 Cloudflare 自动部署到正式线上；部署后再做一遍冒烟测试。

## 6. 分阶段

| 阶段 | 内容 | 产出 |
|---|---|---|
| 1 | 路由器（规则 + Haiku，与预取并行）+ 意图标注集 | 路由准确率、耗时报告 |

## 6.5 已有结果（2026-11-07，本地）

| 测试 | 结果 |
|---|---|
| 意图判断（Haiku 5.5，220 句：任务集 120 条改文档指令 + 自写 100 句） | 改文档 160/160 判对；讨论、闲聊 60/60 判为不改文档；中位 0.7 s，p90 1.0 s |
| 对话者首字 / 整句（从用户说完算，含意图判断，30 句） | Haiku 5.5 1.25 / 2.0 s；Sonnet 5.5 1.5 / 3.2 s；Opus 5.5 2.1 / 3.6 s |
| 改文档速度：S3 vs S3+对话者（60 题 × 2） | 最后一次写入 +20 ms [−473, +552]，整轮结束 +80 ms [−452, +607]：无差别。成功率 85.0% vs 76.7%，但 60 题里 Pi 收到的第一条请求两边逐字相同，差异来自 Pi 自身的随机性 |
| 语音层：同一批 36 句合成中文 | GPT-Live-1：字错率 1.0%（32/36 全对），转写完成 1.01 s，开口 1.47 s（p90 2.1 s）；只把 9/18 条改文档请求委派出去。Boson：字错率 9.8%（29/36 全对），转写完成 0.89 s，开口 1.08 s；7/36 句的转写在句中停顿处就结束、后半句丢失（如"你觉得第三章应该怎么组织"只转出"你觉得？"），而 S3 的 Pi 正是按这段转写干活 |

结论：GPT-Live-1 的中文识别明显更准、更完整；它自己的"委派"不可靠，所以 Pi 必须像设计的那样由服务端按转写直接启动，GPT-Live-1 只负责说话。
